# Game Vault V3

V3 is a focused collection console for Game Vault. It retains the current app's collection, picker, play log, ratings, stats, filters, Google Sheets integration, and PWA update behavior with an arcade-themed skin on the same polished layout: deep indigo panels, neon pink, cyan, and coin-yellow accents, soft glows, and the pixel dinosaurs. The pixel font (Press Start 2P) is used only for the logo and small labels; all reading text is the regular sans.

- V1 remains at `/index.html`.
- V3 runs at `/v3/`.
- V3 has its own stylesheet, manifest, service worker, cache, and install scope.
- Browser storage remains shared with V1 so existing local settings and play data carry across on the same origin.
- **Data connection:** V3 reads and writes only through the owner's Apps Script web app (`google-apps-script/Code.gs`, `GET ?action=data` for reads). The web app URL is entered in Settings or delivered by an invite link, and is stored only in the browser. No sheet links and no collection data are in the V3 source, so the spreadsheet does not need to be published to the web.
- **Invite link:** Settings has "Copy invite link". It puts the web app URL after `#` in the link; opening it connects that device. Anyone with the link has full view and edit access, so the URL should be treated as a password. To revoke access, create a new deployment and update Settings.
- The last synced collection is cached in the browser (`bgv-games`) so the app opens instantly and works offline.
- The active UI is defined only by `cabinet.css`. Its structural rules come first; the `ARCADE LAYER` section at the end holds the arcade skin.
- Icons, app icons, and cleaned dino sprites live in `assets/` and are generated by `python3 tools/build_arcade_assets.py` (needs Pillow).

## Dino Duel Roster

The optional Stats CSV can configure the Scoreboard fighters with these `Key,Value` rows:

```csv
John Dino,Velociraptor
John Color,#36b8c4
Elizabeth Dino,Triceratops
Elizabeth Color,#e9513d
```

Supported dinosaurs are T-Rex, Velociraptor, Triceratops, Ankylosaurus, Brachiosaurus, Pterodactyl, Spinosaurus, and Stegosaurus. Colors must be six-digit hex values.

## Read-only share page

`/share/` is a view-only copy of the collection for sending to other people. It has two tabs, Collection and Favorites, with no forms and no way to save anything. Plays, head-to-head records, the picker, and Settings are not part of it.

- **Live data:** the page loads from a read-only Apps Script feed, `google-apps-script/ShareFeed.gs`. Deploy that script as its own standalone web app (steps are in the file) and paste its `/exec` URL into `FEED_URL` in `share/index.html`. Sheet edits then show up on the next page load, within about a minute.
- **What the feed returns:** game name, shelf, player counts, best at, solo option, BGG score, category, played, expansion, both ratings, BGG link, BGG ID, thumbnail, and the two player names. Notes, prices, tax, shipping, vendor, buy reason, year bought, sell flags, and plays never leave the sheet.
- **What visitors can see:** the feed URL and the fields above. They cannot see the spreadsheet, its published CSV links, or the write-back script.
- **If the feed is unreachable,** the page shows the last copy that browser loaded, with a short notice.
- **Assets:** `python3 tools/build_share.py` copies the stylesheet, icons, and cover map from `v3/` into `share/`. Re-run it after design changes, then re-upload `share/` to the host.
- `share/` is self-contained, so it can be hosted by itself. Hosting it apart from this repository is what keeps the private app and its sheet URLs out of visitors' reach.
